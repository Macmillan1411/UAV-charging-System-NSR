## Naming and change control

Use `T4_<Document_Name>_v<major.minor>_<YYYYMMDD>.<ext>` for new revisions. Existing supplied filenames are retained unless a correction is necessary for file format.

1. Work in a short-lived branch such as `docs/interface-register-update`.
2. Open a pull request describing the change, affected requirements and interfaces, and reason.
3. Obtain review from another team member before merging.
4. Update this manifest for every approved document revision. Never rewrite an already frozen baseline tag.
5. Once all baseline files are present and verified, tag the exact commit `PDR-v1.0`. Subsequent approved changes get `PDR-v1.1` or a new major version.
